# Edizora (Эдизора)

Приложение для подготовки и публикации изображений и новостей в Telegram.

**[Скачать Edizora 0.1 для Windows](https://github.com/TheHolo/edizora/releases/download/v0.1/edizora.exe)** · [Все релизы](https://github.com/TheHolo/edizora/releases) · [Что нового](CHANGELOG.md)

**Приложение для Windows:** [установка без терминала и первый запуск](docs/desktop-quickstart.md). Готовый установщик включает Python и веб-интерфейс; поддерживает LM Studio, Ollama и локальные/облачные сервисы с совместимым API. [Сборка и границы предварительного выпуска](docs/desktop-development.md).

**Новая управляемая веб-версия:** [запуск и переход со старой установки](docs/web-platform-quickstart.md), [установка и перенос](docs/web-platform-deployment-implementation.md), [результаты и границы проверки](docs/web-platform-release-notes.md). В неё входят FastAPI, React/TypeScript, Mini App, общая очередь и управляемый host. Описанные ниже старые способы запуска предназначены для установок, которые ещё не приняты под управление host.

Приватный Telegram-бот для публикации изображений и новостей. Принимает ссылку или текст, собирает редактируемый черновик и публикует его в выбранный канал после подтверждения.

**Основной способ запуска: Windows + LM Studio на одном компьютере.** Один процесс запускает бота и обработчик новостей. VPS, Docker, Ollama и публичный входящий порт для этого не нужны. Старый вариант с отдельным worker сохранён.

## Возможности

- Изображения из Pixiv, DeviantArt и прямых ссылок; редактор альбомов с миниатюрами, выбором кадров и порядком.
- Перевод названий **на английский через LM Studio**; MyMemory подхватывает перевод при ошибке или таймауте.
- Новости из сайтов, YouTube с доступными субтитрами, публичных Telegram-постов, пересылок и ручного текста.
- Локальная переработка новостей через **LM Studio** или Ollama, проверка JSON Schema, обработка длинных источников по частям.
- Редактор заголовка, описания, тегов и подписи; предпросмотр медиа; отдельный редактор новостей.
- Очередь по каналам, интервалы, точное время, пауза, перемешивание и ручная публикация.
- SQLite, восстановление заданий, диагностика и резервное копирование.

## Установка с нуля на Windows

### 1. Подготовьте Telegram и программы

1. Создайте бота у [@BotFather](https://t.me/BotFather) командой `/newbot`, сохраните его токен.
2. Узнайте **числовой ID** своего Telegram-аккаунта, например через [@userinfobot](https://t.me/userinfobot). Username для доступа не подходит.
3. Добавьте бота администратором тестового канала с правом публикации. Для публичного канала можно использовать `@channel_username`; для приватного нужен числовой ID вида `-100…`.
4. Установите [Python 3.12 или новее](https://www.python.org/downloads/windows/) с добавлением в PATH и [LM Studio](https://lmstudio.ai/download). Откройте новый PowerShell после установки.
5. Скачайте проект или выполните `git clone <адрес-вашего-репозитория>`, затем откройте PowerShell в его папке.

Для постоянной работы лучше держать SQLite и storage в локальной папке без синхронизации OneDrive. Если проект уже в OneDrive, можно задать абсолютные пути к данным в `.env` и `bot-settings.toml`, как описано в [конфигурации](docs/configuration.md).

### 2. Установите зависимости одной командой

Из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\setup.ps1
```

Скрипт создаёт **`.venv-local`**, устанавливает зависимости новостного обработчика и копирует `.env.example` в `.env`, если файла ещё нет. Существующий `.env` сохраняется. Активация окружения не требуется; изменение ExecutionPolicy действует только для этого запуска PowerShell.

Если установлен [uv](https://docs.astral.sh/uv/getting-started/installation/), скрипт использует версии из `uv.lock`. Без uv он создаёт окружение через Python и устанавливает совместимые версии через pip. Для воспроизводимой установки используйте uv.

Для разработки добавьте `-Dev`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\setup.ps1 -Dev
```

### 3. Включите сервер LM Studio

1. Откройте LM Studio, скачайте или выберите уже имеющуюся **текстовую instruct-модель** с поддержкой structured output.
2. Загрузите её с контекстом **не меньше 8192 токенов**. Если оперативной памяти/VRAM не хватает, выберите более компактную модель или уменьшите контекст одновременно в LM Studio и настройках worker.
3. На вкладке **Developer** запустите **Start Server**. Адрес по умолчанию: `http://127.0.0.1:1234`.
4. Оставьте сервер доступным только на этом компьютере; для этого сценария режим доступа из локальной сети не нужен.
5. Посмотрите точные ID моделей:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\run-local.ps1 -Models
```

Список показывает текстовые модели и их состояние; embedding-модели исключены. Выбрать модель можно позже командой `/models` в Telegram: нажмите кнопку с нужным названием. Для установленной, но незагруженной модели включите **JIT loading** в LM Studio либо загрузите её вручную. Первый запрос с загрузкой может занять больше времени.

Если в **Server Settings → Require Authentication** включена авторизация, создайте токен и укажите его в `HOME_WORKER_LMSTUDIO_API_KEY`.

Документация LM Studio: [локальный сервер](https://lmstudio.ai/docs/developer/core/server), [JSON Schema](https://lmstudio.ai/docs/developer/openai-compat/structured-output), [каталог моделей](https://lmstudio.ai/docs/developer/rest/list), [авторизация](https://lmstudio.ai/docs/developer/core/authentication).

### 4. Заполните `.env`

Откройте `.env` любым текстовым редактором. Минимальный пример:

```dotenv
BOT_TOKEN=123456789:replace_with_token_from_BotFather
ADMIN_IDS=123456789
DATABASE_URL=sqlite+aiosqlite:///./data/database.db
DEFAULT_CHANNEL_ALIAS=artwork
CHANNELS_JSON='{"artwork":{"chat_id":"@your_test_channel","title":"Мой канал","publish_mode":"auto"}}'

HOME_WORKER_LLM_PROVIDER=lmstudio
HOME_WORKER_LMSTUDIO_BASE_URL=http://127.0.0.1:1234/v1
HOME_WORKER_LMSTUDIO_MODEL=
HOME_WORKER_LMSTUDIO_API_KEY=
```

Замените все примерные значения своими. JSON каналов должен оставаться **одной строкой**, окружённой одинарными кавычками. Несколько администраторов указываются через запятую.

Если в существующей SQLite уже сохранены активные каналы, допустимо оставить `CHANNELS_JSON='{}'`:
локальный запуск использует их, а диагностика показывает число сохранённых каналов.

В локальном режиме `NEWS_WORKER_TOKEN` и `HOME_WORKER_TOKEN` **заполнять не нужно**: секрет создаётся в памяти на время запуска. News API слушает только `127.0.0.1` на порту из `bot-settings.toml` (обычно `8091`). `HOME_WORKER_LMSTUDIO_MODEL` — необязательная начальная модель. Без неё бот запускается; новости ждут выбора через `/models`, перевод названий использует настроенный резерв MyMemory.

Выбрать модель из консоли можно так:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\run-local.ps1 -Model "ID-из-списка"
# Эквивалент:
.\.venv-local\Scripts\python.exe -X utf8 -m app.local --select-model "ID-из-списка"
```

Выбор сохраняется в `storage/lmstudio-model.json` и имеет приоритет над начальной моделью из `.env`/TOML. Перезапуск для дальнейшей смены модели не нужен: новые переводы и ожидающие новости используют выбранную модель. Уже начатая новость завершится на прежней; ранее сохранённые переводы и готовые черновики автоматически не переписываются. Файл выбора привязан к адресу LM Studio; при смене адреса выберите модель заново. Удаление только этого файла возвращает начальную настройку.

Обычные настройки находятся в `bot-settings.toml`; секреты — в `.env`. **Значения TOML имеют приоритет над `.env`**, поэтому не задавайте один параметр в двух местах. Если в файле уже есть `[home_worker]`, дописывайте параметры в существующую секцию.

```toml
# Необязательная настройка в bot-settings.toml
[home_worker]
lmstudio_context_length = 8192
lmstudio_max_predict_tokens = 1600
lmstudio_timeout_seconds = 600
temperature = 0.1
```

`lmstudio_context_length` управляет разбиением текста в боте; фактический контекст модели выставляется в LM Studio. Смотрите [полный справочник конфигурации](docs/configuration.md).

### 5. Проверьте установку

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\run-local.ps1 -Check
```

Проверяются настройки, зависимости, доступность storage, целостность SQLite, локальный API и наличие выбранной модели. `[ERROR]` означает, что причину нужно исправить до запуска. Коды выхода: `0` — проверка пройдена; `1` — ошибка.

Проверка **с реальной генерацией** небольшого тестового черновика:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\run-local.ps1 -SmokeTest
```

Эти команды ничего не отправляют в Telegram и не добавляют тестовую новость в очередь. Обычный `-Check` не проверяет права канала и не гарантирует, что модели хватит памяти; `-SmokeTest` проверяет генерацию и формат JSON, но не качество новостей на всех источниках.

### 6. Запустите бота

Двойной щелчок по **`start-local.cmd`** или:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\run-local.ps1
```

Эквивалентная команда Python:

```powershell
.\.venv-local\Scripts\python.exe -X utf8 -m app.local
```

Остановка — **Ctrl+C** в окне запуска. LM Studio остаётся отдельной программой. Компьютер должен быть включён и не спать, иначе публикация по расписанию не сработает вовремя. Закрытие окна останавливает бота.

В Telegram откройте личный чат с ботом, отправьте `/start`, `/models` и выберите модель, затем `/health full`. Проверьте сначала тестовый канал: `/new` → ссылка → предпросмотр → подтверждение; затем `/news` → короткий ручной текст → готовый черновик.

В одной папке storage разрешён один процесс бота. Не запускайте одновременно локальный режим, `app.main`, Docker или VPS с одним Telegram-токеном. Локальная блокировка не обнаруживает экземпляр на другой машине.

## Ежедневная работа и восстановление

| Команда | Действие |
| --- | --- |
| `/new`, `/news` | создать черновик изображения или новости |
| `/queue [alias]` | открыть очередь |
| `/preview [job_id или alias]` | посмотреть и отредактировать публикацию |
| `/publish [job_id]` | опубликовать без ожидания интервала |
| `/channels` | каналы, интервалы и пауза |
| `/models` | список моделей LM Studio, выбор и обновление списка |
| `/recent`, `/status <id>` | последние задания и состояние |
| `/cancel <id>`, `/retry <id>` | отменить или повторить задание |
| `/stats`, `/health full`, `/help` | статистика, диагностика и помощь |

Если LM Studio выключился, новые новости ждут доступности модели, не расходуя попытки. Работа с изображениями продолжается. При смене ID модели уже созданные новости остаются привязаны к прежней модели; `-Check` предупредит о них. Завершите их прежней моделью либо отмените и создайте снова.

AI обрабатывает **новости и названия локально**. Telegram и загрузка источников требуют интернета.
Если LM Studio недоступен, бот может запуститься: новости ждут модель, названия переводятся через MyMemory.
`-SmokeTest` при этом сообщит об ошибке, поскольку проверяет именно локальную генерацию.

### Редактор альбома

1. Добавьте ссылку через `/new` и выберите канал.
2. В черновике нажмите **«🗂 Редактор альбома»**. Бот покажет до 9 пронумерованных миниатюр на странице.
3. Нажмите номер кадра: его можно включить/исключить, переместить раньше/позже или **сделать первым**.
4. Для быстрого выбора нажмите **«⌨ Порядок номерами»** и отправьте, например, `7,1,5,3`.
   Этот список полностью заменяет выбранные кадры и их порядок. Для отмены ввода — `/cancel`.
5. Нажмите **«👁 Предпросмотр»**, затем **«Готово → черновик»** и подтвердите публикацию.

Кнопки «Первые 10», «Очистить выбор» и «Исходный выбор» помогают собрать альбом заново.
Каждое изменение сразу сохраняется в SQLite. После перезапуска откройте `/recent`, затем `/preview <id>`.
Исключённые кадры остаются в исходном каталоге и доступны для возврата.

Для большого альбома сначала выбираются первые `pixiv_max_images` кадров (по умолчанию 10); карточка
предупреждает об этом и предлагает редактор. При `pixiv_media_limit_enabled = false` можно выбрать больше:
Telegram отправит несколько групп/сообщений по 10 кадров максимум. Первый кадр задаёт порядок отправки;
расположение плиток в опубликованном альбоме определяет Telegram.

Редактор доступен до постановки в очередь. У старых черновиков, созданных до редактора с выбором `[1,3,…]`,
сохранились только выбранные кадры: для доступа ко всему исходнику добавьте ссылку заново.

### Перевод названий

Название переводится **на английский**, оригинал остаётся в подписи. Используется тот же
`HOME_WORKER_LMSTUDIO_MODEL`, адрес и API-ключ, что заданы выше. Дополнительная модель не нужна.
В `bot-settings.toml`, секция `[bot]`:

```toml
auto_translate_titles = true
translation_lmstudio_timeout = 60
translation_fallback_mymemory = true
translation_timeout = 5
```

Бот ждёт LM Studio до 60 секунд, затем при ошибке, неверном ответе или таймауте обращается к MyMemory
с ожиданием до 5 секунд. Если оба сервиса недоступны, сохраняется оригинальное название.
После ошибки локальный перевод временно пропускается на 30 секунд, чтобы новые черновики не зависали на каждом запросе.
Успешный перевод сохраняется в черновике и повторно используется после перезапуска; изменение названия запускает новый перевод.
Для коротких названий с японской каной и корейскими символами язык MyMemory указывается явно.

При резервном переводе **текст названия отправляется внешнему MyMemory**. Для работы без внешнего
переводчика задайте `translation_fallback_mymemory = false`; для полного отключения перевода —
`auto_translate_titles = false`. MyMemory принимает до 500 байт UTF-8; более длинные названия переводятся только локально.

### Резервная копия и обновление

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\run-local.ps1 -Backup
```

SQLite копируется согласованно, включая изменения из WAL, в `backups/publisher-....sqlite3`. Копия содержит задания, каналы и историю; `.env` и медиа в неё не входят. Храните их отдельно. Для восстановления остановите бота и сохраните текущие файлы базы; затем замените базу проверенной копией (подробнее в [развёртывании](docs/deployment.md)).

Перед обновлением остановите бота, сделайте копию, обновите исходники и повторите `setup.ps1`, `-Check` и `-SmokeTest`. Скрипт установки не меняет ваши настройки и не загружает модели.

## Частые проблемы

| Сообщение/симптом | Что сделать |
| --- | --- |
| Нет BOT_TOKEN / ADMIN_IDS | заполнить `.env`; ID — число, токен выдаёт BotFather |
| API LM Studio недоступен | Developer → Start Server; проверить порт 1234 и адрес в `.env` |
| HTTP 401/403 от LM Studio | задать API-токен с нужными разрешениями |
| Модель отсутствует | `-Models`, затем скопировать точный ID текстовой модели |
| Ошибка JSON / ответ обрезан | проверить structured output модели, увеличить лимит ответа, отключить reasoning в LM Studio при необходимости |
| Нехватка памяти / переполнение контекста | уменьшить модель или согласовать контекст в LM Studio и `[home_worker]` |
| Нет `trafilatura` / других зависимостей | повторить `setup.ps1`; использовать `.venv-local` |
| Бот отвечает «нет доступа» | проверить числовой ADMIN_IDS; начать личный чат с `/start` |
| Telegram Conflict | остановить другую копию с тем же токеном |
| Порт 8091 занят | остановить другой worker API или сменить `news_api_port` в `[bot]` |
| После перезапуска пропал шаг ввода | открыть сохранённый черновик через `/recent` или `/preview` |

## Другие варианты запуска

- **Только изображения:** `python -m app.main` в установленном окружении; локальная модель не нужна.
- **Ollama на том же компьютере:** `HOME_WORKER_LLM_PROVIDER=ollama`, `HOME_WORKER_OLLAMA_MODEL=<установленная-модель>`; запуск через `app.local`.
- **VPS + домашний worker:** `app.main` на сервере и `news-home-worker` дома; здесь токены и имя модели синхронизируются вручную. [Инструкция](docs/news-publications.md).
- **Linux/systemd или Docker для основного бота:** [развёртывание](docs/deployment.md). Docker Compose не включает домашний AI-worker; Windows + LM Studio запускайте нативно по инструкции выше.

## Разработка

```powershell
.\.venv-local\Scripts\python.exe -X utf8 -m pytest -q
.\.venv-local\Scripts\python.exe -X utf8 -m compileall -q app
```

Тесты используют временные базы, подмену Telegram и локальные тестовые HTTP-серверы; рабочие токены и настоящая модель не нужны. Зависимости закреплены в `uv.lock`; обновляйте lock осознанно через `uv lock --upgrade` с последующим запуском тестов.

```text
app/bot/         Telegram-интерфейс
app/news/        извлечение новостей, LM Studio/Ollama, worker API
app/services/    публикация, подписи, очередь и предпросмотр
app/local.py     локальный запуск и диагностика
app/runtime.py   совместный жизненный цикл и блокировка экземпляра
deploy/          скрипты Windows, systemd и обновление Linux
tests/           тесты
docs/            справочник, разбор оформления и идеи
```
