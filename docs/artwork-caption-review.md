# Разбор оформления постов с изображениями

Проверены сборка подписи (`CaptionService`), карточка подтверждения, редактор и сохранённые в локальной SQLite
задания Pixiv. Пример ниже основан на записи с названием «狼と香辛料 20th 🎉 赫萝/ホロ», автором «茶泡饭»
и одним изображением. Также проверены записи с японским описанием и альбомом из 15 изображений.
Это разбор данных и сформированной подписи; фактический вид изображения в клиенте Telegram здесь не оценивался.

## Что было в посте

```text
🖼 狼と香辛料 20th 🎉 赫萝/ホロ

🎨 茶泡饭
🔗 Оригинал на Pixiv
📅 24.02.2026

🏷 #ホロ #狼と香辛料 #狼与香辛料
```

Название выделяется жирным, автор и оригинал — ссылки. Если перевод уже получен, он раньше добавлялся прямо
к названию в скобках `(TL: …)`. Если есть описание, бот вставляет до 240 очищенных символов перед автором.
Теги в примере — исходные; фактическая публикация может также содержать пользовательские теги.

Основа удачная: автор и оригинал видны, текст отделён от служебных данных, источник не теряется.
Основная проблема для русскоязычного канала — необработанные иностранные названия/описания и несколько вариантов
одного понятия в тегах. Например, три тега выше связаны с персонажем и произведением, но удобнее выбирать
единые редакционные теги через словарь соответствий, сохраняя исходные отдельно.

## Что исправлено сейчас

1. **Корректный лимит подписи.** Раньше считалась длина HTML вместе с `href`; длинная ссылка могла убрать
   полезный текст или привести к ошибке при короткой видимой подписи. Теперь считается текст после разбора
   HTML и entities, с сохранением переносов строк. Это соответствует правилу
   [Telegram Bot API](https://core.telegram.org/bots/api#sendphoto).
2. **Теги сохраняются по приоритету.** При нехватке места удаляются по одному с конца. Пользовательские теги
   находятся раньше исходных; больше не исчезает весь список сразу.
3. **Перевод вынесен отдельно.** Оригинальное название остаётся жирным, перевод — строкой курсивом `↳ …`.
4. **Уточнена дата.** «Дата оригинала» не смешивается со временем публикации в вашем канале.
5. **Добавлен размер альбома.** Для нескольких выбранных файлов появляется `📚 Изображений: N`.
6. **Убрана ложная атрибуция прямых файлов.** Домен прямой ссылки больше не выводится под иконкой художника.
   Если у автора нет URL, его имя отображается без пустой ссылки.
7. **Карточка черновика стала короче.** Название, автор и теги не повторяются над готовой подписью;
   показаны ID, источник, файлы, канал, время и счётчик `N / 1024`.
8. **Ошибка шаблона объясняется явно.** Неизвестный placeholder приводит к сообщению о `caption_template`.
   Старый `{title}` сохранён для совместимости пользовательских шаблонов.

Для того же примера стандартная подпись теперь выглядит так:

```text
🖼 狼と香辛料 20th 🎉 赫萝/ホロ

🎨 茶泡饭
🔗 Оригинал на Pixiv
📅 Дата оригинала: 24.02.2026

🏷 #ホロ #狼と香辛料 #狼与香辛料
```

Если перевод существует, он появится между заголовком и пустой строкой. Для альбома между датой и тегами
будет строка количества файлов. Существующие посты в канале не редактируются: изменения касаются новых
предпросмотров и будущих публикаций с автоматическим шаблоном.

## Какие поля уже есть и что стоит изменить

| Поле | Сейчас | Предлагаемое развитие |
| --- | --- | --- |
| Название | импортируется; можно изменить | хранить отдельно исходное и редакционное, кнопка восстановления оригинала |
| Перевод названия | английский через LM Studio; MyMemory при ошибке или таймауте | словарь имён и терминов; отдельный перевод описания |
| Описание | импортируется, можно изменить/очистить | отделить комментарий автора от редакционного; переключатель «показывать описание» |
| Автор и профиль | берутся у провайдера | редактируемое имя для атрибуции, проверка ссылки, отдельный соавтор |
| Ссылка на оригинал | обязательная часть автоподписи | сохранять как неизменяемую атрибуцию даже при редакционных правках |
| Дата источника | берётся у провайдера | переключатель видимости в профиле оформления канала |
| Теги | пользовательские + исходные | словарь «Холо / ホロ / Holo», исключаемые теги и 3–5 основных тегов канала |
| Изображения | редактор миниатюрами, порядок, первый кадр, «выбрано 5 из 15», сохранение в SQLite | отмена последних действий, сохранённые подборки |
| Серия/персонаж | обычно только в тегах | необязательные поля «Произведение», «Персонаж», «Рубрика» |
| Предупреждение о содержимом | `content_warning` есть в модели, UI его не использует | явный переключатель спойлера для поддерживаемых медиа; ручное решение редактора |
| Канал, время, режим | доступны в текущем интерфейсе | сохранять набор как профиль публикации, добавить календарь |
| Собственная подпись | заменяет автоматическую целиком | режим «мой текст + обязательный блок автора и оригинала» |

## Предлагаемый следующий вариант оформления

Пример редакционной подачи, **не автоматический перевод исходного названия**:

```text
🖼 Холо — к 20-летию «Волчицы и пряностей»

🎨 茶泡饭 · Оригинал на Pixiv

#холо #волчица_и_пряности #иллюстрация
```

Предлагаю сделать три профиля на канал: **компактный** (пример выше), **подробный** (описание, дата, размер
альбома) и **архивный** (оригинальное название, автор, источник, дата). Новая схема полей должна сохранить
исходные данные независимо от выбранного профиля. Редактор выбирает стиль, а бот показывает точный результат.

Порядок внедрения: локальный перевод → словарь тегов → профили оформления → редактор альбома.
Общий план новых возможностей находится в [отдельном документе](roadmap.md).
