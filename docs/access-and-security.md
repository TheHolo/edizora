# Доступ и безопасность

Бот рассчитан на приватное администрирование. Ниже описаны границы защиты и обязанности оператора.

## Доступ к Telegram-интерфейсу

`ADMIN_IDS` содержит числовые Telegram ID через запятую:

```env
ADMIN_IDS=123456789,987654321
```

Middleware проверяет `event_from_user` до запуска обработчика сообщения или callback. Неизвестный пользователь получает отказ, а событие без пользователя не выполняет команду.

Username вида `@name` не используется как право доступа: он может измениться. Пустой список администраторов закрывает доступ всем.

Все указанные администраторы могут видеть и управлять общими заданиями. Разделения jobs по владельцу между администраторами нет.

## Секреты

В `.env` хранятся:

- `BOT_TOKEN`;
- `PIXIV_COOKIES`;
- `NEWS_WORKER_TOKEN`;
- `HOME_WORKER_TOKEN`;
- `HOME_WORKER_LMSTUDIO_API_KEY`, если включена авторизация LM Studio;
- credentials базы или прокси, если они есть.

`bot-settings.toml` хранится в Git и принимает только белый список несекретных параметров. Попытка добавить туда неизвестный ключ или токен останавливает запуск.

Лог-фильтр скрывает Telegram bot token, Bearer Authorization, cookie, password, поля вида `*_token`, `*_api_key`
и учётные данные в URL. Форматтер применяет ту же очистку к traceback исключений.

Локальный launcher связывает бота и worker временным секретом в памяти, принудительно слушает loopback
и не требует внешнего news API. Клиенты LM Studio, Ollama и worker API не следуют HTTP-перенаправлениям.

Не вставляйте реальные секреты в сообщения Telegram, issue, commit или документацию. После утечки отзовите токен, а не только удалите его из последнего commit.

## Безопасность пользовательских URL

Для произвольных HTTP(S)-источников запрещены:

- URL с логином или паролем;
- literal IP, если он не глобальный;
- DNS-имя, указывающее хотя бы на один неглобальный адрес;
- небезопасные перенаправления загрузки медиа;
- нестандартные порты в news fetcher.

Основной прямой HTTP-клиент и домашний extractor используют `PublicOnlyResolver`. Он проверяет те DNS-адреса, которые aiohttp реально передаёт в подключение, и закрывает обычное окно DNS rebinding между предварительной проверкой и соединением.

При работе через явно настроенный HTTP/SOCKS-прокси конечный DNS может выполняться прокси. Безопасность и правила DNS такого прокси также находятся в зоне ответственности оператора.

## Ограничения HTTP

News fetcher ограничивает:

- число перенаправлений;
- размер распакованного ответа;
- Content-Type;
- общее время запроса;
- допустимые домены для специальных источников.

DownloadService отдельно ограничивает размер реального потока и удаляет незавершённый `.part`.

## News API

API домашнего worker включается только непустым `NEWS_WORKER_TOKEN` и использует `Authorization: Bearer ...` со сравнением постоянного времени.

Он принимает только узкий набор операций:

- lease задачи;
- progress/heartbeat;
- complete;
- fail;
- health.

Каждая активная задача имеет отдельный случайный lease token. Complete, progress или fail с истёкшим/неверным token отклоняются.

API не имеет TLS внутри приложения. По умолчанию он слушает loopback. Для удалённого доступа используйте SSH-туннель, WireGuard/Tailscale или reverse proxy с HTTPS и дополнительным сетевым ACL.

Не публикуйте порт `8091` на `0.0.0.0` без защищённого внешнего слоя.

## Ollama

Домашняя конфигурация принимает `ollama_base_url` только с loopback host. Это не даёт случайно выставить незащищённый Ollama API в локальную сеть или интернет.

Текст источника считается недоверенным. Системный prompt требует игнорировать инструкции внутри него, но финальный текст всё равно должен проверить человек.

## Telegram и HTML

Название, описание, автор, ручной текст и сообщения worker экранируются перед отправкой с `parse_mode=HTML`. Теги проходят нормализацию. Пользовательский `caption_template` считается доверенной конфигурацией администратора.

## Хранение данных

База содержит Telegram ID администраторов, исходные ссылки, тексты черновиков, статусы, ошибки, `file_id`, подписи и историю подписчиков. Ограничьте права на каталог приложения и резервные копии.

Для systemd unit включены `NoNewPrivileges=true` и `PrivateTmp=true`. Процесс запускается отдельным системным пользователем.
