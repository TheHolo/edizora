# Диагностика и восстановление

До запуска Telegram на Windows используйте `deploy/run-local.ps1 -Check` (или `python -m app.local --check`).
Команда проверяет конфигурацию, зависимости, storage, SQLite и локальную модель. `-SmokeTest` дополнительно
создаёт пробный черновик только в памяти. `-Models` выводит ID моделей; `-Backup` сохраняет согласованную SQLite-копию.
Эти режимы не запускают Telegram polling и не публикуют сообщения. Полная инструкция находится в [README](../README.md).

Команда `/health` проверяет основные зависимости, а `/health full` добавляет более дорогие сетевые и дисковые проверки.

## Быстрая проверка

Быстрый отчёт содержит:

- `Database` — запрос `SELECT 1` и задержка;
- `Workers` — число живых workers, занятые задания и heartbeat;
- `Queue` — число ожидающих, возраст старейшего и зависшие активные задания;
- `Publications` — последняя успешная публикация;
- `Failures` — ошибки и неопределённые публикации за 24 часа;
- `Channels` — число активных каналов, основной канал и согласованность lease;
- `Storage` — существование, доступ на запись и свободное место;
- `Telegram` — доступность Bot API.

Красная строка делает весь отчёт unhealthy. Жёлтая означает предупреждение, которое не блокирует работу прямо сейчас.

## Полная проверка

`/health full` дополнительно:

- определяет размер SQLite или PostgreSQL;
- проверяет запись и удаление временного файла в storage;
- проверяет права публикации для каждого включённого канала;
- показывает последнюю публикацию отдельно по каналам;
- выполняет короткие probes Pixiv и DeviantArt.

Недоступный внешний provider даёт предупреждение, а не делает всего бота unhealthy. Ошибка Telegram, базы, storage, workers или прав канала считается критической.

## Автоматическое восстановление jobs

При старте WorkerPool восстанавливает незавершённые задания:

- `downloading` и `processing` возвращаются в `queued` или `scheduled`;
- задание с запросом отмены становится `cancelled`;
- `publishing` становится `failed` с кодом `uncertain_publish`;
- lease канала освобождается.

Публикация из состояния `publishing` специально не повторяется: Telegram мог уже принять запрос до перезапуска.

Периодический watchdog может восстанавливать только старые активные задания, не трогая свежую работу живого worker.

## Восстановление news-задач

News-task выдаётся домашнему worker на ограниченное время. Heartbeat продлевает lease. Если последняя попытка истекла, задача становится `failed`, пользователь получает обновление статуса, а другой worker её больше не забирает.

Повторяемая ошибка до исчерпания попыток возвращает задачу в `queued`. Отмена очищает lease и делает последующие progress/complete запросы недействительными.

## Неопределённая публикация

Код `uncertain_publish` используется, когда:

- Telegram не ответил после запроса отправки;
- отправлена только часть нескольких сообщений;
- бот перезапущен на этапе `publishing`.

Действия администратора:

1. открыть целевой канал;
2. проверить последние сообщения;
3. если пост присутствует — не повторять задание;
4. если поста точно нет — создать новый осознанный повтор.

Массовый retry пропускает такие задания.

## Частые проблемы

### Бот не запускается

Проверьте конфигурацию и журнал:

```bash
python -m app.main
sudo journalctl -u edizora -n 100 --no-pager
```

Частые причины: пустой `BOT_TOKEN`, ошибочный JSON каналов, неизвестный ключ в `bot-settings.toml`, недоступный путь SQLite или неверный часовой пояс.

### Бот не публикует

Запустите `/health full`. Проверьте `can_post_messages`, chat ID, паузу, `enabled` и время ближайшей публикации.

### Задание ждёт домашний worker

Проверьте:

- запущен ли `news-home-worker`;
- совпадают ли `NEWS_WORKER_TOKEN` и `HOME_WORKER_TOKEN`;
- работает ли туннель/VPN;
- совпадает ли имя модели;
- отвечает ли Ollama на `127.0.0.1:11434`.

Однократная проверка:

```bash
news-home-worker --once
```

### Не работает SOCKS-прокси

Установите extra и перезапустите процесс:

```bash
python -m pip install -e '.[proxy]'
```

Если заданы и `HTTP_PROXY`, и `SOCKS_PROXY`, используется SOCKS.

## Наблюдение systemd

```bash
sudo systemctl status edizora
sudo journalctl -u edizora -f
```

Unit автоматически перезапускает процесс через 5 секунд. Не запускайте рядом второй экземпляр с тем же токеном.
