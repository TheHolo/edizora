# Имя и версия Edizora

Название приложения — **Edizora**, русское произношение — **Эдизора**. Первый выпуск — **0.1**, Git-тег — `v0.1`, установщик — `edizora.exe`.

Имя и версия Python находятся в `app/branding.py`, метаданные пакетов — в `pyproject.toml` и `frontend/package.json`. Сборка проверяет совпадение версий backend, frontend и параметра сборщика. Свойства EXE используют ProductName=Edizora и ProductVersion=0.1; числовой формат Windows — 0.1.0.0.

Новые установки сохраняют данные в `%LOCALAPPDATA%\Edizora`. Если найдена прежняя установка в `%LOCALAPPDATA%\Publisher`, приложение продолжает работать с её данными. Миграция имени не перемещает работающие базы данных. Старый AppId установщика сохранён для обновления на месте; запись автозапуска переводится на Edizora.

Для новых настроек используются `EDIZORA_*`. При запуске они нормализуются в прежние внутренние имена `PUBLISHER_*`, которые остаются совместимыми с уже установленными узлами. Если заданы обе формы, используется `EDIZORA_*`.

Сохранённые форматы резервных копий и релизов, криптографические метки, HTTP-заголовки, cookies, блокировки и имена служб уже установленных управляемых Linux-узлов сохраняют прежние технические идентификаторы. Это обеспечивает совместимость данных и защиту от запуска двух отправителей. Новые архивы исходников имеют префикс `edizora-`; проверка принимает и старые `publisher-` архивы.

Документы в `audit/` и изображения в `output/ui-concepts/` — исторические материалы до переименования. Их названия и пути к исходным доказательствам сохранены.

Исходники и выпуски Edizora: `TheHolo/edizora`. Установщик доступен в разделе GitHub Releases.

Для прежней ручной установки systemd скрипт `deploy/update.sh` принимает старые пути через `SERVICE_NAME=telegram-image-publisher`, `APP_USER=telegram-publisher` и `APP_ROOT=/opt/telegram-image-publisher`. Новые ручные установки используют имя `edizora`; управляемые Linux-узлы сохраняют совместимые служебные имена.
