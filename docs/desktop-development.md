# Сборка и проверка устанавливаемого Publisher

## Архитектура

`app.desktop.launcher` запускает изолированную от checkout локальную установку. Мастер первого запуска слушает случайный loopback-порт; секрет запуска передаётся во фрагменте адреса и удаляется из истории страницы. Изменения требуют секрет в заголовке и точное совпадение Origin/Host. Пароли и секреты не передаются через query string. Подготовка новой установки проходит в staging с журналом завершения перемещения папок.

Приложение использует существующие host/runtime, идентичность, блокировки отправителя, SQLite, авторизацию и backup/restore. Повторный запуск открывает действующий экземпляр. Фоновый запуск не создаёт второй runtime. Значок в трее использует штатную остановку с завершением начатых отправок.

AI-подключения и worker credentials зашифрованы в машинном SecretStore. В интерфейс возвращаются только открытые параметры. Host запускает RegisteredWorker через существующий протокол аренды; рабочие секреты подключений не передаются в окружение runtime и в переносимый пакет секретов. Профили переключаются явно, доступен отдельный выбор для news/title_translation. Добавление подключения поддерживает повтор Idempotency-Key без второго worker.

Сборка PyInstaller содержит Python, frontend, зависимости, значок, уведомления о лицензиях и проверяемый ZIP исходного релиза для штатного переноса. Диспетчер дочерних процессов разрешает только фиксированные модули runtime/desktop. Inno Setup устанавливает приложение под текущим пользователем, сохраняет данные при удалении и не завершает отправитель принудительно. Перед обновлением создаётся локальная копия остановленного data/control.

## Команды для разработчика

На Windows x64 нужны Python 3.12+ с поддержкой выбранной версии PyInstaller, uv, Node.js и Inno Setup. Эти инструменты нужны только машине сборки.

```powershell
uv sync --frozen --extra dev --extra news-worker --extra desktop --extra desktop-build
npm --prefix frontend ci
npm --prefix frontend run build
powershell -NoProfile -ExecutionPolicy Bypass -File deploy/build-desktop.ps1 -Compiler 'C:\path\ISCC.exe'
```

Результат: `output/desktop/Publisher-Setup-0.2.0-windows-x64.exe`, SHA-256 и папка `bundle/Publisher` для проверки самостоятельного запуска. Сборщик не читает `.env`, рабочие БД или storage; release ZIP формируется по штатному списку файлов исходников.

```powershell
python -m pytest tests/test_desktop.py -q
$env:PUBLISHER_TEST_EXECUTABLE = (Resolve-Path output/desktop/bundle/Publisher/Publisher.exe).Path
python -m pytest tests/test_desktop_bundle.py -q
npm --prefix frontend run test:client
```

Для проверок legacy используйте `PUBLISHER_TEST_TMP_ROOT` вне OneDrive. В ограниченной среде также задайте доступные TEMP/TMP и UV_CACHE_DIR.

## Границы предварительного выпуска

Не настроены публичный канал доставки обновлений, сертификат издателя, публичная страница скачивания и служба поддержки. Пересборка и повторный запуск установщика обновляют программу с локальной копией данных; автоматического отката несовместимой схемы нет. Для публичного выпуска нужны решение об имени/издателе, лицензия самого проекта, подпись пакетов и независимая чистая Windows-машина.

Новый установщик не доказывает работоспособность внешних SSH-переносов, DNS/HTTPS, Mini App или конкретного облачного AI. Эти проверки выполняются отдельно на тестовых аккаунтах. Совместимые AI должны поддерживать JSON Schema; универсального адаптера ко всем существующим протоколам нет.
