## Реализовано

- FastAPI и версионированные контракты; общие application services для Telegram, браузера и Mini App. Контроль версии записи, идемпотентные команды, неизменяемый подготовленный план, журнал отправок и сохранённые операции.
- React/TypeScript: публикации и галерея, создание/редактор/автосохранение/конфликты, альбомы, очередь, календарь, история, AI, каналы, размещение, backup/restore, настройки и диагностика. Данные приходят из backend. Демонстрационные материалы находятся только в отдельном тестовом профиле.
- Разделённые host/runtime: блокировка единственного процесса, роли/поколения, общая остановка, drain принятых обработчиков/отправок, сохранение входящих Telegram update и восстановление незавершённых операций. Неопределённая отправка не повторяется автоматически.
- Локальный доверенный вход, Argon2id, серверные сессии, CSRF/Origin/Host, Telegram initData/replay/TTL, bearer Mini App в памяти, отзыв credentials. Длительные чувствительные операции используют ограниченный допуск текущей сессии только для данного operation/action.
- Зарегистрированные исходящие домашние AI-исполнители, одноразовая привязка, каталог/выбор модели, lease/heartbeat/revocation, предложения перевода и отдельное применение. Подготовленная очередь не требует доступного домашнего компьютера.
- SQLite upgrade с резервной копией, отдельный control store, приватное хранилище секретов, шифрованная переносимость credentials без переноса пользовательских сессий.
- Windows/Ubuntu 24.04 x86-64 installers; пассивное назначение и явная первоначальная активация чистой установки. Отдельное принятие остановленной legacy установки с копированием SQLite/storage, защитой старого launcher и общей паузой.
- План/прогресс/проверка переноса Windows → Ubuntu, Ubuntu → Windows и Ubuntu → Ubuntu; SSH с закреплённым fingerprint, память для вводимых SSH credentials, пассивное provision той же версии, исходящий Windows bridge, manifest/hash/ID validation, durable retirement/grant/receipt и разрешение потерянного ACK. Backup/restore, расписание/retention и ручная проверка восстановленной очереди.
- Воспроизводимый ZIP с manifest и хешем каждого файла, frontend source/dist, lock-файлами, OpenAPI/генерируемыми типами, тестами, установщиками и руководством. Рабочие `.env`, БД, media, machine keys и сессии в релиз не включаются.

## Не выполнено во внешней среде

В этой сессии отсутствуют разрешённый тестовый Telegram-канал, два чистых Ubuntu узла, публичный HTTPS-домен и Telegram Android/iOS/Desktop. Поэтому остаются непроверенными:

1. Чистая установка/повтор/upgrade/restart на отдельных Windows и Ubuntu ОС, реальные systemd/Caddy/ACL/sudo и ограничения диска.
2. Настоящие SSH-переносы во всех трёх направлениях, Windows NAT, сетевые обрывы на checkpoint, DNS/HTTPS routing, проверка реальных host keys.
3. Отправка одиночного материала/альбома/новости и ручное разрешение неопределённого Telegram результата на тестовом канале; фактическое меню/команды бота.
4. Mini App по HTTPS отдельно в Android/iOS/Desktop: initData, BackButton, safe areas, внешние ссылки, закрытие/возврат и экранная клавиатура.
5. Реальная генерация подключённой LM Studio/Ollama и приёмка задержек/нагрузки на согласованном сервере.

Точный сценарий с подготовкой и сверкой результатов находится в конце [руководства развёртывания](web-platform-deployment-implementation.md); сценарий клиентов — в [UI-отчёте](web-platform-ui-implementation.md). Для исполнения нужны именно тестовые доступы/машины. Полная внешняя приёмка продукта не объявляется завершённой.

## Эксплуатационные ограничения

Перенос не совмещается со сменой релиза: источник и назначение должны использовать один проверенный пакет. Поддерживаемый профиль provision — Ubuntu 24.04 LTS x86-64. Существующая чужая Caddy-конфигурация не перезаписывается. После перезапуска controller SSH-пароль/ключ вводится заново. Для восстановления полных секретов нужен пароль копии; машинный ключ отдельно хранится защищённо. Потеря control identity требует восстановления, а не назначения роли по наличию SQLite.

Первое принятие legacy требует корректно остановленного старого runtime и его автозапуска, совпадения путей с исходной конфигурацией и новой пустой локальной папки. Оно оставляет общую паузу и старую очередь для проверки/подготовки. Копирование уже управляемых данных не выдаёт права публикации. При сбое принятия marker и блокировка остаются для явного восстановления; автоматического запуска старого источника нет.

Одна предупреждающая запись регрессии относится к deprecation Starlette TestClient/httpx; ошибок тестов из-за неё нет. Реальные внешние испытания нужны до включения боевого отправителя.
