# Идеи развития и результаты проверки

Это отдельный список следующих улучшений. Возможности в разделе «Уже сделано» реализованы в текущих изменениях;
таблицы приоритетов ниже описывают предложения.

## Уже сделано

- LM Studio подключён через локальные `/v1/models` и `/v1/chat/completions`: JSON Schema, API-токен при необходимости,
  ограниченные повторы, проверки ответа и запрет HTTP-перенаправлений. [Документация протокола](https://lmstudio.ai/docs/developer/openai-compat/structured-output).
- Обработка длинного текста выделена из Ollama в общий компонент, чтобы исправления работали для обоих провайдеров.
- Одна команда запускает Telegram и worker; модель и временный секрет согласуются автоматически, API привязан к loopback.
- Установка Windows, отдельное `.venv-local`, `uv.lock`, диагностика, пробная генерация без Telegram и SQLite backup.
- До получения следующего задания worker проверяет доступность модели, сохраняя попытки во время простоя AI-сервера.
- Совместная остановка процессов обработки, блокировка второй копии в той же storage-папке, освобождение ресурсов
  при ошибке инициализации.
- Валидация основных полей канала до старта, очистка API-ключей и учётных данных из логов и traceback.
- Исправлены лимит подписи, сохранение приоритетных тегов, оформление перевода/даты/альбомов и карточка черновика.
- Редактор альбомов в Telegram: миниатюры, выбор и порядок кадров, первый кадр, ввод номеров, предпросмотр,
  сохранение полного исходника и выбора в SQLite, защита от устаревших и одновременных правок.
- Английский перевод названий через LM Studio с резервом MyMemory, таймаутами и кэшем; перевод сохраняется в черновике.

## Что показала проверка кода

| Проблема | Следствие | Решение |
| --- | --- | --- |
| Жёсткая привязка к Ollama | нельзя использовать LM Studio без изменения кода | добавлен отдельный транспорт и общая обработка текста |
| Ручное согласование имени модели | worker может бесконечно не получать задачи другой модели | в локальном режиме ID один; диагностика показывает старые задачи другой модели |
| HTML-строка считалась целиком | подпись обрезалась из-за длинных URL | считается видимый текст; добавлены регрессионные проверки |
| Теги исчезали все сразу | пользовательские теги терялись вместе с исходными | удаление по одному с конца списка |
| Пустая/ошибочная конфигурация | исключение или недоступный бот после запуска | проверка полей и команда диагностики |
| Трассировки обходили фильтр сообщения | секрет в исключении мог попасть в лог | фильтрация окончательно отформатированного сообщения |
| Зависимости новостей отсутствовали в окружении этой машины | отдельные источники не могли работать | установлены в `.venv-local`; setup всегда включает news-worker |

Проверка не равна независимому аудиту безопасности всех внешних источников. Новые границы проверяются тестами;
для реальной эксплуатации отдельно нужны успешный smoke-test выбранной модели и проверка тестового Telegram-канала.

| Профили оформления каналов | единый стиль без редактирования HTML | компактный/подробный/архивный, переключатели даты/описания/перевода, предварительный показ |

## Приоритет 3: эксплуатация и устойчивость

- **Автозапуск Windows с журналами и перезапуском после сбоя.** Отдельный установщик задания планировщика,
  проверка LM Studio, ограничение частоты перезапусков, команда удаления автозапуска. Сейчас поставляется ручной запуск.
- **Плановые резервные копии и срок хранения.** Текущая команда создаёт одну проверенную копию SQLite;
  добавить расписание, хранение нескольких версий, включение конфигурации без секретов и контроль восстановления.
- **Очистка временных файлов.** `files_ttl_hours` объявлен, но не запускает очистку. Нужен сборщик,
  удаляющий только файлы завершённых/отменённых заданий и осиротевшие previews; активные задания не трогать.
- **Миграции схемы.** Заменить ручные additive migrations на последовательные версионированные миграции,
  проверяемые на копиях существующей SQLite. Делать до расширения таблиц профилями и ревизиями.
- **Публикация после сна компьютера.** Выбор политики для просроченных постов: пропуск, равномерное распределение,
  ручное подтверждение. Не отправлять неожиданно всю накопившуюся очередь подряд.
- **Метрики генерации.** Сохранять время, модель, число частей и повторов; показывать оценку очереди и причины ошибок.
- **Пауза обработки и выбор модели в Telegram.** Настройка должна применяться к будущим задачам либо сопровождаться
  явным переназначением старых; смена только строки в `.env` не переименовывает уже сохранённые новости.

## Что исправлять следующим в существующих функциях

1. **`TranslationService`:** кроме локального провайдера, ограничить размер кэша и добавить TTL. Сейчас кэш растёт
   без ограничения, а временная ошибка сохраняется как `None` до перезапуска.
2. **Редактор:** текущие шаги ввода хранятся в MemoryStorage. Сохранять этап диалога либо автоматически возвращать
   пользователя к последнему открытому черновику после перезапуска.
3. **Предупреждения изображения:** поле `content_warning` пока не подключено к редактору/отправке. Сделать видимый
   переключатель спойлера с предварительным показом, не применять скрыто по догадке модели.
4. **Длинные источники:** текущий бюджет контекста оценивается по символам. Добавить проверку по токенизатору
   выбранной модели; это точнее для смешанного русского, японского текста и JSON.
5. **Правки опубликованного:** отдельная функция исправления подписи по сохранённым `message_ids`, с просмотром
   изменений и журналом. Сейчас редактирование сосредоточено на черновиках и очереди.

Следующая итерация: **профили оформления + словарь тегов + история правок**.
Локальный перевод названий и редактор альбомов уже реализованы. Далее можно добавить локальную панель,
расширенный поиск и сбор новостей из RSS.
