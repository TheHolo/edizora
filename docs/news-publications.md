# Новости и домашний AI-worker

Новостной режим создаёт редактируемый Telegram-пост из внешнего источника. Модель работает локально
через LM Studio или Ollama. В [локальном режиме](../README.md) бот и worker находятся в одном процессе
на Windows; отдельный VPS не требуется. Схема VPS + домашний worker также поддерживается.

## Запуск с LM Studio на одном компьютере

Заполните `HOME_WORKER_LLM_PROVIDER=lmstudio`, `HOME_WORKER_LMSTUDIO_MODEL` и адрес сервера в `.env`,
проверьте `python -m app.local --check`, затем запустите `python -m app.local` из окружения с extra `news-worker`.
Или используйте `deploy/run-local.ps1`. Токены синхронизируются автоматически, ID модели берётся из настройки worker.

Перед получением задания worker проверяет доступность модели. Если сервер выключен, новые задачи ждут,
не расходуя попытки. Уже начатый запрос при отключении сервера всё ещё может завершиться ошибкой и повториться.
Авторизация и другие постоянные HTTP-ошибки не вызывают повторную генерацию; временные ошибки и невалидный JSON
имеют ограниченное число повторов. Подробности: [справочник конфигурации](configuration.md).

## Источники

Бот принимает:

- обычную статью по публичной HTTP(S)-ссылке;
- YouTube-видео;
- отдельный пост публичного Telegram-канала;
- пересланный боту Telegram-пост или альбом;
- текст, введённый вручную.

Закрытые ссылки `t.me/c/...` не извлекаются. Если пост нельзя открыть публично, его можно переслать боту.

## Поток обработки

1. Telegram-бот сохраняет короткое задание в таблицу `news_tasks`.
2. Домашний worker запрашивает следующую подходящую задачу.
3. API бота выдаёт lease с одноразовым токеном и сроком действия.
4. Worker извлекает текст и метаданные источника.
5. LM Studio или Ollama создаёт структурированный черновик.
6. Worker проверяет результат и возвращает его API бота.
7. Бот создаёт обычный редактируемый `Job` в статусе ожидания подтверждения.
8. Администратор проверяет пост, меняет его при необходимости и ставит в очередь.

Во время работы одно статусное сообщение обновляется по этапам. Кнопка отмены завершает lease; домашний worker узнаёт об этом при следующем heartbeat и прекращает локальную работу.

## Что извлекается

### Сайты

Основной текст извлекается через Trafilatura. Структурированные данные страницы читаются через extruct и используются как дополнительные метаданные. Размер ответа и число перенаправлений ограничены.

### YouTube

Метаданные получает `yt-dlp`, а текст — `youtube-transcript-api`. Сначала worker ищет субтитры на настроенных языках, затем может использовать другие ручные субтитры. Само видео не скачивается и не транскрибируется аудиомоделью.

### Публичный Telegram

Для ссылки на пост используется публичная embed-страница. Из неё берутся текст, автор, дата и доступные изображения. Удалённые видео и документы по внешней ссылке VPS не скачивает: перешлите сам файл боту или добавьте его в редакторе.

### Пересланный пост

Telegram `file_id` сохраняется и повторно используется при публикации. Это позволяет отправлять фото, видео, анимации и документы без скачивания файла на VPS. Альбом собирается коротким debounce-окном и дедуплицируется.

## Работа модели

Worker передаёт модели недоверенный текст и отдельно указывает игнорировать инструкции внутри источника. Ответ должен соответствовать строгой JSON-схеме:

- заголовок до 160 символов;
- лид до 400 символов;
- основной текст до 2800 символов;
- до 5 предложенных тегов;
- список использованных фактов и предупреждений.

Если источник не помещается в контекст, worker делит его на части, извлекает факты из каждой части и иерархически сокращает evidence. Если безопасно уместить данные всё равно нельзя, задача завершается ошибкой вместо потери части источника.

На VPS возвращаются черновик, метаданные и SHA-256-подтверждение обработанного текста. Полная длинная статья или расшифровка не копируется обратно.

## Настройка домашнего компьютера

Склонируйте проект на домашний компьютер, откройте терминал в корневой папке
проекта — там, где находятся `pyproject.toml`, `.env.example` и
`bot-settings.toml`, — затем установите зависимости и модель:

```bash
python -m pip install -e '.[news-worker]'
ollama pull gemma4:12b
```

Под «домашним `.env`» имеется в виду файл `.env` именно в этой папке проекта
на домашнем компьютере. Это не `.env` на VPS и не системный файл Windows или
Linux. Если файла ещё нет, создайте его копированием примера:

Linux/macOS:

```bash
cp .env.example .env
```

Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

Откройте созданный `.env` в любом текстовом редакторе и заполните параметры
домашнего worker:

```env
HOME_WORKER_TOKEN=replace_with_a_long_random_secret
HOME_WORKER_VPS_API_URL=http://127.0.0.1:8091
HOME_WORKER_OLLAMA_BASE_URL=http://127.0.0.1:11434
HOME_WORKER_OLLAMA_MODEL=gemma4:12b
HOME_WORKER_LLM_PROVIDER=ollama
```

`HOME_WORKER_TOKEN` — общий секрет, которым домашний worker подтверждает своё
право получать задачи от VPS и возвращать результаты. Формат токена специально
не ограничен, но он должен быть непустым, случайным и трудным для подбора.
Рекомендуется не меньше 32 случайных байт. Например, безопасное значение можно
сгенерировать так:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Сохраните полученную строку: на следующем шаге её нужно посимвольно скопировать
на VPS. Имена переменных на двух машинах различаются, но значения одинаковы:

```env
# Домашний компьютер: .env
HOME_WORKER_TOKEN=SeCrEtWoRdFoRlLm

# VPS: .env
NEWS_WORKER_TOKEN=SeCrEtWoRdFoRlLm
```

`SeCrEtWoRdFoRlLm` здесь только наглядный пример — не используйте его как
настоящий секрет. Не добавляйте `.env` в Git и не отправляйте токен в сообщения.

Секцию `[home_worker]` в расположенном рядом `bot-settings.toml` нужно менять
только для нестандартных лимитов, размера контекста или интервалов. Секрет в
TOML переносить нельзя.

Запуск:

```bash
news-home-worker
```

Команду запускайте из корневой папки проекта, чтобы worker нашёл домашние
`.env` и `bot-settings.toml`.

## Настройка VPS

На VPS откройте `.env` в корневой папке установленного проекта и добавьте
`NEWS_WORKER_TOKEN`. Его значение должно в точности совпадать со значением
`HOME_WORKER_TOKEN` на домашнем компьютере:

```env
NEWS_WORKER_TOKEN=replace_with_the_same_long_random_secret
```

В `bot-settings.toml` на VPS проверьте настройки API:

```toml
[bot]
news_api_host = "127.0.0.1"
news_api_port = 8091
news_task_lease_seconds = 1800
news_model_name = "gemma4:12b"
```

Пустой `NEWS_WORKER_TOKEN` полностью отключает news API и создание новостей.

## Защищённое соединение

News API использует Bearer-токен, но токен не заменяет шифрование. Для удалённого VPS используйте SSH-туннель или VPN. Пример туннеля с домашнего компьютера:

```bash
ssh -N -L 8091:127.0.0.1:8091 user@your-vps
```

После этого `HOME_WORKER_VPS_API_URL=http://127.0.0.1:8091` остаётся локальным адресом.

Ollama разрешён только на loopback-адресе. Worker специально отклоняет конфигурацию, которая пытается открыть Ollama по внешнему адресу.

## Повторы и зависшие задачи

Worker периодически продлевает lease. Временные ошибки могут вернуть задачу в очередь, пока не исчерпан `max_job_attempts`. Истёкшая последняя попытка переводится в ошибку и больше не выдаётся worker.

Модель worker должна совпадать с `news_model_name` задачи. Это не позволяет случайно обработать задачу другой моделью, но после смены модели старые задачи потребуют worker с прежним именем или ручного пересоздания.

## Ограничения

- модель может ошибаться: итоговый черновик всегда нужно проверить;
- текст Telegram-поста не может превышать 4096 видимых символов;
- в публикации не больше 10 медиаэлементов;
- защищённый Telegram-контент не обрабатывается;
- автоматическая аудиотранскрипция YouTube не выполняется;
- локальная модель и её файлы требуют места и подходящей памяти/VRAM.
